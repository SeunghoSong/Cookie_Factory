| 2 | C2 → C3 전처리 데이터 | 판정팀 내부 | 전처리 결과 포맷(리사이즈 크기, 정규화 여부), 메타데이터(frame_id, timestamp) 포함 여부, **SAM 2 프롬프트 타입 및 좌표 스펙**(아래 2-1 참조) |

| 4 | C4 → C1 역전송 | 수집팀 내부 | 마킹된 프레임 재전송 방식, 원본 프레임과의 매칭 키(frame_id) |
| 5 | 공통 | 전체 | 원형도 임계값(threshold) 초기값 합의 (예: 0.75 미만 = 불량), 에러/타임아웃 처리 방식 |
| 6 | 공통 | 전체 | 포트 번호 및 네트워크 구성(Docker network 이름, ngrok 포워딩 대상 포트) |

### 2-1. SAM 2 프롬프트 생성 전략 (필수 확정 사항)

SAM 2는 프롬프트(포인트/박스) 입력이 필수인 모델이므로, 실시간 자동화를 위해 아래 방식을 채택한다.

| 항목 | 결정 사항 |
|---|---|
| 프롬프트 방식 | **Box Prompt** (수동 클릭/Automatic Mask Generator 방식은 제외) |
| 생성 위치 | C2 (Preprocessing) 담당 |
| 생성 로직 | 배경(컨베이어 벨트, 단색 가정) 대비 이진화(`cv2.threshold`) → `cv2.findContours` → 최대 면적 컨투어의 bounding box 추출 |
| 전제 조건 | 프레임당 검출 대상 과자 1개 등장 가정 (다중 객체 시 최대 컨투어만 선택, 나머지 무시) |
| C2 → C3 전달 데이터 | `{frame_id, timestamp, image, box_prompt: [x_min, y_min, x_max, y_max]}` |
| C3 처리 | `SAM2ImagePredictor.set_image(image)` → `predict(box=box_prompt, multimask_output=False)` → 단일 마스크 반환 |
| 실패 예외 처리 | 컨투어 미검출(빈 프레임/배경만 존재) 시 C2가 `box_prompt: null` 전달 → C3는 판정 스킵 후 "No Object" 상태로 C1 통보 |

> **리스크**: 조명 불균일/배경-객체 대비 부족 시 컨투어 탐지 실패 가능. 데모 전 배경(벨트) 색상과 과자 색상 대비가 확보된 촬영 환경(고정 배경지 등)을 사전 준비할 것.

> **권장**: JSON 스키마와 포트 정의는 11:20까지 공유 문서(또는 슬랙 핀)에 고정하고, 이후 변경 시 즉시 상대방에게 통보.

## 7. 데모 시나리오 (16:00 최종 확인)

1. 담당자가 QR 코드를 스마트폰으로 스캔 → 모바일 웹 접속
2. 카메라 권한 허용 → 실시간 프레임 스트리밍 시작
3. 정상 과자 → 원형도 0.9 이상 → "정상(Pass)" 표출
4. 깨진/찌그러진 과자 제시 → 원형도 저하 감지 → "불량(Fail)" 마킹 및 표출
5. 검출률 집계 결과 공유
